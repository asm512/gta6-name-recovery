You are helping recover hashed identifier names from a game engine's metadata (RAGE engine, GTA/RDR lineage). A brute-force tool will try every 1 to 4 word combination of a vocabulary against the unknown names of ONE metadata file. Your job: write the vocabulary for that file.

Read the digest (Read tool): {SRC}
It lists the file's structs with the field names already known and how many fields of each type are still unknown.

Work out what the file is about, then write the words most likely to appear in the UNKNOWN struct and field names. Think like the programmers who named the known ones: same domain, same style. Include:
- every word the known names are built from (split CamelCase: "MaxResponseTime" gives Max, Response, Time), common ones first
- many more domain words those names suggest but do not contain: synonyms, opposites and counterparts (Min/Max, Enter/Exit, Left/Right), related mechanics, units, the nouns and verbs a designer of this system would use
- the abbreviations this codebase uses (Mult, Coeff, Dist, Anim, Ptfx, Vfx, Fx, Lod, Ik, Fov, Veh, Ped, Obj, Pos, Rot, Vel, Accel, Min, Max, Num, Idx, Id, Info, Params, Tunables, Settings, Data, Def, Flags, Hash, Name)
- generic identifier glue (Is, Has, Can, Use, Should, Allow, Enable, Disable, Force, Ignore, Override, On, In, To, For, Of, With, When, If, By, At, Per, No, Not, All, Any, Only)

Rules: single words only, letters only, each written Capitalised (e.g. Speed, Ptfx, Ik), no duplicates, most likely first because rank matters to the search. Aim for 700 to 1000 words. Do not include type prefixes like f or b on their own.

Write the list with the Write tool to: {DST}
Format: plain text, words separated by spaces or newlines, nothing else. Do not run commands or touch other files. Reply with just the number of words written.
